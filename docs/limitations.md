# Prototype limitations

- **Small language.** Five types and seven generators cover practical flat fixture cases. There are no nested objects, arrays as field values, decimal numbers, free-form expressions, regex generators, schemas, timestamps, localization, imports or custom functions.
- **Flat relations.** A relation points to an earlier table's `id` generated by `seq`. Self, forward, cyclic, composite and transitive relation targets are rejected. Dangling-reference generation is not yet a language feature.
- **Deliberate faults, limited constraints.** `id` does not implicitly enforce uniqueness. Missing, null and duplicate are intentional rules. There are no uniqueness assertions, conditional constraints, arbitrary invalid type overrides or user-authored validation predicates.
- **One global random stream.** Editing declaration order or extending an earlier table may change later random values. Stable per-field streams, statistical distributions and cryptographic randomness are outside version 0.1.
- **Finite output.** Fixed budgets limit rows, cells and strings. The interpreter materializes the complete dataset in memory. Browser export also creates a complete string and download blob, so this is not a streaming multi-gigabyte generator. The UI previews only the first 100 rows of a selected table.
- **CSV has fewer states than JSON.** Missing keys, explicit nulls and empty strings become empty CSV fields. CSV has no intrinsic type declarations. Use JSON when a test depends on these distinctions. Spreadsheet mode changes some payload strings and cannot guarantee safety across every spreadsheet implementation or later conversion.
- **Basic editing.** The playground is a labeled plain-text editor, not a full IDE. Diagnostics stop at the first error. There is no completion engine, formatter, multi-file workspace or persistence across browser sessions.
- **Node and modern browser.** The included setup requires Node.js and a browser with ES modules and Web Workers. It is intended for loopback use. It has not been packaged as a desktop application or production server.
- **Testing scope.** Automated tests and browser checks establish specific checked behaviors; they do not prove all programs safe or all browser versions compatible. See [testing and verification](QA.md) for the recorded scope and exclusions.
- **Demo documentation.** The included demo outline is a recording script, not an executable test or a video file.
